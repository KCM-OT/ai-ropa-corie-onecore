Built by hand

OneCore 0.7.0 has no component for these, so they're native HTML styled with --oc-* tokens. Highlighted items have a OneCore option the build should use instead.

Microphone button on the start screen Use OneCore

A hand-drawn microphone glyph on a plain button, using the browser's speech recognition.

Use button[ocAssistantDictation] from the assistant entry point, which this prototype doesn't use yet.

AI input on the start screen Check with OneCore

Figma Main-AI-Prompt: grey rounded field, paperclip left, microphone that becomes a round dark Send button once there's text, 58px minimum height growing with the text, white with a floating shadow when focused.

Consider oc-assistant-composer with button[ocAssistantAttach], button[ocAssistantDictation] and button[ocAssistantSubmit], restyled to the design, so attachments, dictation and keyboard handling come from OneCore.

Sample prompt pills Check with OneCore

White rounded pills that fill the AI input with a sample; they don't send it.

Consider button[oc-assistant-suggestion] with fill-on-click (setPromptOnClick) once the start input is a composer.

App shell: top bar and side navigation

Dark sidebar with logo, search, collapse animation, grouped nav with icons, Demo mode switch; top bar with Ask Copilot, notifications, tenant and user.

OneCore has no side nav or app bar. Styled with tokens, plus one local token for the near-black background.

Page header

Title, breadcrumb and header actions.

No OneCore page header. shell/page-header.ts.

Data tables

Processing activities and Pending inventory: sortable headers, selection, row menus, footer.

No OneCore table. Native <table> with the shared .data-table styles in src/styles.scss; footer wraps oc-pagination.

History cards

Name, completeness badge, one-line summary, Document or Prompt, creator avatar, date. The whole card opens the session.

Native buttons. oc-card isn't interactive, so check with OneCore before swapping.

Draft record panel

Record basics, completeness, field list with evidence quotes, linked inventory, checks and posture.

Layout built from tokens; uses Badge, Status, Tag, Progress, Skeleton and Alert inside.

Likely-duplicate panel and decision card

Caution panel with the matched record, rationale and overlapping-fields table; a card in the chat with three choices and Confirm.

Caution yellow from --oc-supportive-yellow tokens; the card uses Radio group and Button.
