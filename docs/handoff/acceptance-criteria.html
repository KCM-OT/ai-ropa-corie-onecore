Acceptance criteria

Testable behaviour for each feature of the OneCore RoPA prototype, written as Given / When / Then. Each criterion has an ID to reference in tickets and tests, and each feature links to its section in the screen specs. All of them pass in the prototype; those tagged Stand-in are met by a mock that production must replace.

App shell

Spec

any page is loaded or reloaded
Then
the Demo mode switch is on, the navigation shows only "AI Assisted RoPA Creation" and the module name "Data Mapping Automation" stays visible
SHELL-02Turning demo mode off shows the full navigation
Given
demo mode is on
When
the user turns the switch off
Then

SHELL-03Home goes to the right page

they land on AI Assisted RoPA Creation when demo mode is on, and on Processing activities when it's off

Processing activities

Spec

Given
the list is showing
When
the user types in Search
Then
only rows whose name, ID, managing organization or owner contain the text (any case) remain, and the table returns to page 1
PA-02Sorting
Given
the list is sorted by Name ascending (default)
When
the user selects a sortable header
Then
a new column sorts ascending, the same column toggles direction, and the header's aria-sort and arrow icon match
PA-03Saved views use review dates
When
the user picks "Overdue reviews" or "Due in 30 days"
Then
the list shows records whose next review (last reviewed + cadence) is past, or within 30 days, of today
PA-04Unsaved view changes are flagged
Given
a search term is entered or the sort isn't Name ascending
Then
a bold * beside the saved view reads "View has unsaved changes"
PA-05Selection
When
the user checks the header checkbox
Then
every row on the current page is selected and highlighted; the header shows indeterminate when only some are; selections persist across pages
PA-06Pagination
When
the user changes rows per page (10, 20, 50, 100)
Then
the table returns to page 1 and the footer reads "Showing {first}–{last} of {total}"
PA-07Add processing activity menu

PA-08Create a variation from a record

PA-09Empty result

the table shows "No processing activities match this view."
PA-10Drafts banner
Given
AI drafts are waiting

Author with AI

Spec

Given

Drafting conversation

Spec
CHAT-01Too little to draft
Given
the first message is under 60 characters with no readable file
Then
the assistant asks for who the data is about, what's collected and why, tools, retention and storage, and nothing is created
CHAT-02Extraction summary
Given
a usable description or document
Then
the reply states how many values and linked items were found and that each value quotes its source
CHAT-03Unreadable attachments are named
Given
an attached file isn't plain text
Then
the reply says it can't read that file and which types it reads Stand-in
CHAT-04Record details in three steps
Given
there's no unresolved duplicate
Then
steps for record name, owning group entity and role replace the composer; Continue stays disabled until name and entity are set; the steps can be closed and reopened with "Add record details" without losing answers
CHAT-05Role is pre-selected from the text
Given
the description contains a role cue (e.g. "on behalf of our clients")
Then
that role is pre-selected and the quote is shown as "Suggested: {role}, from “…”"; the user can change it
CHAT-06Questions in the skill's order
Then
follow-ups come one at a time: missing items, low-confidence values, warnings by severity, unresolved tools, then values to confirm; each shows "(n to go)" or "(Last one)"
CHAT-07Answer, chip or skip
When
the user answers, picks a chip or selects "Skip this question"
Then
the answer updates the record (re-checked immediately) or the field is marked "Skipped. Left for the reviewer."; the next question follows
CHAT-08Confirm values
When
the user selects "Yes, that's right" or "Confirm the rest"
Then
that value, or every remaining "Needs review" value, is marked as the user's
CHAT-09Stop and edit
When
the user selects Stop while a reply streams
Then
the partial reply is removed, the turn's changes are undone, the message reads "Reply stopped" and can be edited and resent
CHAT-10Ready summary
Given
no questions remain
Then
the assistant summarises completeness, required assessments, open checks, review cadence and anything left for the reviewer, and the badge reads "Ready to send"
CHAT-11Replies stream Stand-in
Then
a thinking indicator shows first, then the reply streams in; with reduced motion it appears without animation

Spec
PANEL-01Layout split
Then
the chat takes 30% of the width (at least 260px) and the draft 70%; at 640px or wider the draft shows fields in two columns and Checks beside Posture
PANEL-02Skeleton while creating
When
the first description is sent
Then
the panel shows a skeleton of the whole record and the badge "Creating" until the first reply finishes; screen readers hear "Creating the draft record"
PANEL-03Skeleton on changed fields
When
a field, name, entity or role changes after the draft exists
Then
that block shows a skeleton (fields with a teal left edge) for about a second, then the new value; fields appearing for the first time don't flash
PANEL-04Provenance is visible
Then

PANEL-05Completeness by role
Then

PANEL-06Remove a linked item
When

Then
it leaves the record and the checks re-run
PANEL-07Checks and posture follow the skill
Then
Checks list the skill's warnings by severity with any recorded answer; Posture lists triggered conditions, required assessments with owners and the review cadence; results match ropa_check.py (parity test)

Duplicate check

Spec
User storyAs a Privacy Program Manager, I want the agent to identify likely duplicate processing activities before I create a new record, so that I avoid creating redundant RoPA entries.
DUP-01Checked before anything is created
Given
the user sends a description, attaches a document, or starts from an existing record
Then
the draft is compared with existing processing activities before the record-details step
DUP-02Only records the user can view Stand-in
Then
the comparison uses only records the user is permitted to view, and never reveals a record outside that scope (prototype: every group entity except APAC)
DUP-03Likely duplicate is presented
Given
a record scores 0.33 or more
Then
the best match is shown in caution yellow with its name and ID, a short rationale, a Strong or Likely match label, and the badge "Possible duplicate"
DUP-04Overlapping fields are listed
Then
a table shows only the fields that overlap (activity, vendors and systems, data subjects, personal data, clients, owning entity), with this draft's values beside the matched record's
DUP-05Three structured actions
Then
the conversation offers Use existing record, Create as local variation with inheritance, and Dismiss duplicate flag as one choice, with Confirm; free text can't stand in for a choice
DUP-06Nothing happens until Confirm
Given
a choice is selected but not confirmed
Then
no record is created, linked or inherited from, the draft is unchanged, and Send to Pending inventory stays disabled; Confirm is disabled until a choice is made
DUP-07Use existing record
When
the user confirms Use existing record
Then
no record is created or sent, the badge reads "Not created", the panel says "Using {name} (#{id})", and "Start a new record" returns to the start screen
DUP-08Local variation inherits
When
the user confirms Create as local variation
Then
the draft shows "Local variation of {name} #{id}"; each shareable field the draft lacks takes the parent's value marked "Inherited"; the user's own values stay; the link and inherited fields go to Data Mapping with the record
DUP-09Starting from a record
Given
the user chose Create variation with AI on a record
Then
the check flags that record, the rationale includes "you started from this record", and the same three actions apply
DUP-10Dismiss is recorded
When
the user confirms Dismiss duplicate flag
Then
the record continues unlinked, the panel shows "Not a duplicate of {name}", and "Not a duplicate of {name} (#{id}). Flag dismissed by {user}." is sent to the reviewer
DUP-11No duplicate found
Given
no record scores 0.33 or more
Then
the assistant says it checked and found no likely duplicates, and record details open
DUP-12The card can be hidden
When
the user hides the decision card
Then
the composer returns with "Review likely duplicate", which reopens it; any message sent instead is answered with a prompt to choose and confirm

Send to Data Mapping

Spec
SEND-01When Send is available
Then
"Send to Pending inventory" is enabled only once the record has a name and group entity, no reply is streaming, and no duplicate decision is pending
SEND-02Confirmation first
When
the user selects Send to Pending inventory
Then
a dialog "Send to Pending inventory?" explains that Data Mapping opens in a new tab with the record as a Pending draft to approve; Cancel, Escape, close or an outside click sends nothing
SEND-03Hand-off to Data Mapping Stand-in
When
the user selects "Send and open Data Mapping"
Then
Data Mapping's Processing activities opens in a new tab with the record added as a Pending row, marked as created with AI, with a confirmation and "Show record"
SEND-04Complete package
Then
the record carries every value with its evidence, confidence and provenance, kept relationships, check results, notes and any duplicate decision
SEND-05Sent state
Then
the badge reads "Sent", questions stop, and the footer shows "{name} was sent to Data Mapping" with "Open Data Mapping" and "Download JSON"
SEND-06Blocked new tab
Given
the browser blocks the new tab
Then
the alert reads "Your browser blocked the new tab. Open Data Mapping to add it to Processing activities." and "Open Data Mapping" completes the hand-off
SEND-07No duplicates in Data Mapping
Given
the same package arrives twice (reload, second click)
Then
only one row is created; an invalid package or unknown group entity is refused with a message and nothing is added

Accessibility

A11Y-01Keyboard reachable
Then
every control on every screen works from the keyboard and shows a visible focus ring
A11Y-02Focus moves with the flow
Then
opening the record-details steps or the duplicate card moves focus into it; closing either returns focus to the composer; the dialog traps focus and returns it to Send
A11Y-03Everything is named
Then
icon-only buttons, the AI input, the Demo mode switch, row checkboxes ("Select {name}") and row menus ("Actions for {name}") have accessible names
A11Y-04Changes are announced
Then
loading and status messages (drafting, creating, sent, attachment errors, the start-screen hint) are in live or status regions; skeletons are hidden from screen readers
A11Y-05Reduced motion
Given
the user prefers reduced motion
Then
sidebar, skeleton shimmer, streaming and the dictation pulse don't animate
A11Y-06Colour isn't the only signal
Then
confidence, status, completeness and caution states also carry a text label
